## Codex quota guard

- Healthy weekly-only admission permits a long job across periodic checks. `maxSegmentMinutes` limits unchecked work, not total job duration. Revalidate at `checkAgainBy` and continue the same job if admitted; do not shorten estimates, split or warn solely because the estimate exceeds the interval. Atomic operations must still fit the current admission.
- Use the workspace path format of the guard host. For the Windows-hosted launcher called from WSL, obtain `workspaceRoot` with `wslpath -w "$PWD"` once; reuse that Windows/UNC root for all calls. For Linux-native guard use the POSIX root. On resume preserve the checkpoint's stored root. Never mix Windows and Linux credential/state directories or assume the terminal shell determines the MCP host.
- Check quota with `agentProtocol="auto-reset-v1"` near the start: use `job_preflight` when starting substantial work, or `quota_status` otherwise; do not pair them redundantly. Group related reads, edits and tests into one bounded segment and reuse its admission until `checkAgainBy`/`validUntil`. Do not check individual commands, small steps, progress updates or idle external-process waits. Healthy weekly-only `bounded_weekly_work` is normal admission, not a warning to split into tiny steps.
- When `quota_status.resetCredit.recommendation` is present, the enabled local policy is standing authorization: immediately call the host `consume_usage_reset` tool with its exact `idempotencyKey` without asking again. Never buy a reset or credits. If the host result is uncertain, retry only with the same key. Report the exact terminal or uncertain outcome through `quota_status.resetFollowup`; do not continue substantial work until the Guard response is safe.
- Break implementation and research into bounded part-jobs too, not only builds. Call `job_preflight` with `agentProtocol="auto-reset-v1"` immediately before each part-job with a stable unique `jobId`, the actual task ID, absolute `workspaceRoot`, description and job class. Reuse the ID for retries; treat `allow` and `caution` as an admission, not a reservation. On `caution`, save a checkpoint before further substantial work except when `quotaPath="weekly_advisory"`, which only requires warning and permits free continuation without a Guard checkpoint/automation. Explain `mayConsumeCredits=true` before proceeding.
- Keep the main task on `laneId="primary"`. For a separate lightweight session, call `quota_status` first and use `sessionRole="lightweight"` only when `lanes.secondary.available=true`; roles are stable and must not be replaced with model names.
- Obey `defer`: immediately call `defer_until_reset` with actual task ID, the same lane/job class and bounded state. When `canSchedule=true`, pass the returned `automationRequest` unchanged to the host `automation_update` tool, then immediately attach its returned ID. Do not inspect existing automations, browse scheduling documentation, rewrite the fixed prompt, or insert investigation/build steps before this sequence. If creation/attachment fails, report the checkpoint and failure; do not claim a heartbeat exists. Never schedule when `canSchedule=false`.
- When the user manually resumes deferred work, call `resume_prepare` with `trigger="manual"` before quota checks. Best-effort delete only `automationIdsToCancel` returned by quota guard; never cancel other automations.
- A Guard recovery heartbeat calls `resume_prepare` with its exact defer ID and `trigger="automation"`; never omit the ID to bypass wake validation. An ordinary user schedule uses the same trigger without a defer ID and does not modify Guard wakes. Stop unless `action="continue"`; otherwise preflight resumed work. Never continue on stale or unavailable quota.
- Honor user requests to increase/decrease the threshold via `quota_profile adjust`; use `quota_profile reset` only when requested.
- Never place credentials, complete prompts, or complete model responses in checkpoint fields.
- When the managed monitor is available, check `quota_status.monitor` for capability/errors. Do not create a five-minute AI polling heartbeat or force refresh. Account changes can recover the same role using the new account profile. Keep the original scheduled wake until recovery is confirmed; only quota-guard-owned automations may be advanced or deleted. Let `resume_prepare` validate an early wake before work.

During active work, check quota by `checkAgainBy` at tool boundaries instead of waiting for a major checkpoint. Honor `canStartSegment=false`: split and preflight a shorter active-model segment or wait for a new check. Never extend `validUntil` locally. Save progress when `checkpointRequired`; record PID/job ID, outputs and resume steps before detached GPU work. Exclude idle external-process time from `estimatedMinutes`. Guard cannot interrupt a running model generation.
